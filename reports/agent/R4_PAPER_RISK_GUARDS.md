# R4 PAPER risk guard correction — local stage

The archived R4 patch highlighted defects that still existed at current HEAD: Bybit `PaperAccountService::resume` could change a blocked account to ACTIVE without owner approval; `PositionLifecycleService` could silently reactivate a Bybit account when equity recovered; the entry eligibility check treated null drawdown as eligible; and externally supplied risk configuration could relax the established hard ceilings. The full R4 patch was not applied. This unit ports only the verified PAPER safety controls.

`resume` now requires an explicit owner-approved argument for any blocked/halted-to-ACTIVE transition, rejects negative drawdown, and writes an append-only journal event in the same transaction on an approved transition. The CLI exposes the explicit flag but does not auto-approve. Lifecycle refresh retains BLOCKED/HALTED status across equity recovery. Entry eligibility rejects null, malformed, or negative drawdown. `RiskEngine` and `PositionSizingService` enforce existing ceilings: 0.50/0.25/0.10% by quality, 1.50% total open risk, 200% notional, 2x model leverage, 5% entry block and 10% halt. Configuration may tighten these values. Default policy values were not raised, and no account was reactivated in this work.

Changed source: `app/PaperTrading/Application/{PaperAccountService,PaperExecutionEligibilityService,PositionLifecycleService,PositionSizingService,RiskEngine}.php`, `app/PaperTrading/Console/PaperAccountCommand.php`, and `app/Providers/AppServiceProvider.php`. Changed tests: `tests/Feature/PaperTrading/AccountSafetyRegressionTest.php` and `tests/Unit/PaperTrading/RiskAndSizingTest.php`.

Focused tests on isolated PostgreSQL 17.11 `bybit_test` passed 40 tests, 84 assertions, exit 0. Negative controls cover recovery without reactivation, refusal without approval, durable journal on an explicitly approved synthetic test-account transition, bad drawdown, relaxed configuration, unsafe sizing, and exact default boundaries. The approved synthetic transition is test evidence only, not a production owner decision. Other R4 research/evolution changes and R6 topology/global risk remain unintegrated.

The complete PHP suite passed after this change: 1,184 passed, 9 skipped, 11,137 assertions, 180.05 s, exit 0. `vendor/bin/pint --test` passed 743 files, exit 0. Syntax validation passed 723 PHP files, exit 0. No production account status or financial history was changed.
